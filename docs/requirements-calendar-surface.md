## 1. 摘要

在周历和月历恢复日期格边缘光束，让窗口边框和组件底面响应同一个外观透明度滑杆，并缩小日程区的日期标题。交付的单张设计图展示 360 × 620 紧凑月视图、60% 材质、18 日选中、鼠标悬停 19 日的状态。

## 2. 评审与验收

需求提出方确认三项视觉变化。设计评审确认光束强度、组件透底与字号层级。前端负责实现和 Web 回归，macOS 验收负责在实际 Tauri 窗口核对透明度和输入操作。具体责任人随开发任务确定。

## 3. 背景

v0.3.9 将日期悬停改为换底，并给顶栏、日历和日期标题使用不透明表面。反馈截图中，壁纸透过了窗口空白，但面板仍呈现大块白底。红线标出「今天 · 11月18日」，它是本次字号调整的控件。截图的日期、0 待处理和月视图作为原型示例数据。

## 4. 目标与验收结果

| 优先级 | 需求 | 验收结果 |
| --- | --- | --- |
| P0 | 周、月日期格 hover 光束 | 指针进入日期格时立即出现，只有指针下的一格有光束。鼠标移出后清除，滚动或切换格子时没有残影。 |
| P0 | 窗口与组件材质同步 | 在 60% 档，组件底面和边框均显示背景细节。文字、数字、图标和键盘焦点仍清晰。100% 档冷启动首帧起彻底不透底。 |
| P0 | 优化红线处标题字号 | 标准档紧凑窗从 21 px 降至 18 px，字重从 720 降至 660。同一行可看见日期标题和待处理计数。 |
| P0 | 保留日期操作 | 选中日期、今天下划线、周数字、月圆点、方向键焦点与 Enter／空格选中均可正常使用。 |

## 5. 使用场景

主要用户是在 macOS 桌面挂件中查看当天待办或切换日程的用户。鼠标用户需要判断当前将要点击哪一天，键盘用户需要定位焦点，使用高透底设置的用户仍需读清日期、计数和操作。范围包括紧凑和展开窗、浅色和深色、周和月视图。

## 6. 设计取舍

光束作为短暂的指针提示。当前日期继续用下划线区分，选中日期用填色区分，键盘焦点保留独立外环。所有可见底面共用同一档材质透明度，组件之间靠轻微的色差、描边和留白分隔。日期标题降低字号和字重，保留「星期三 → 日期标题 → 筛选」的阅读顺序。

## 7. 开发规格

设计图见 [60% 紧凑月视图预览](../output/ui-design/calendar-surface-60.png)。图中光束停在经过右上圆角的一帧。

### 7.1 日期格边缘光束

- 使用细指针悬停触发。覆盖本月、跨月、今天、已选中的可点击日期格。每次进入新格立即启动，按 **900 ms 单圈**运行：移动段为 `stroke-dasharray: 16 84` 的短蓝青划段，`stroke-dashoffset` 从 0 线性走到 -100，沿现有圆角扫完整一圈。结束帧移动段透明，只停在静态淡描边，不留移动 trace；移出、切视图、窗口失焦或开始拖动时清除。
- 光束宽度建议 **1.5 CSS px**，蓝青渐变。沿日期格现有圆角走，不占布局空间。日期文字、计数／圆点在上层，既有选中底色和今天下划线保持可辨。
- 键盘导航沿用独立 `:focus-visible` 外环。焦点与悬停可同时显示，同页方向键与 Enter／空格选择不熄灭悬停光束；只有跨页等确实替换视图时才清除。`prefers-reduced-motion: reduce` 下，悬停从第一帧就用静态描边，移动段保持透明。触屏不显示粘滞的 hover。
- 前端优先沿用日期按钮，用无事件的伪元素或同等级装饰层绘制。仅悬停格运行过渡或动画。遮罩效果在 WKWebView 不可用时回退为静态描边。点击范围、DOM 焦点和布局尺寸保持既有行为。

### 7.2 底面与边框统一透明度

- 延用设置项「外观透明度」的 **55%–100%、5% 步进**和已有持久化。**60% 指材质不透明度 alpha = 0.60，背景贡献 40%**。60% 是本稿的演示值。
- 同一值应用于窗口底面、窗口描边、顶栏、日历、日程标题及筛选、清单／事项卡、空态、设置与新增／编辑浮层的面材质和控件填充。文字、图标、角标内容及焦点环独立绘制。控件状态通过填色与文字色维持辨识度，避免白字在浅玻璃按钮上失去对比。
- 嵌套组件处，同一像素只应用一次用户 alpha。通过合并装饰材质后统一合成，或通过等效的非重叠分区实现。两层 60% 直接叠加会形成 84% 的覆盖率，达不到面板和外框同步的效果。材质组只包含装饰层，不在交互内容祖先上套整窗 `opacity`。
- 保持现有首帧设置读取和拖动／失焦状态管理。100% 应用实际不透明的材质。55%、60%、75%、95% 按档位透底。尊重系统「降低透明度」设置，启用时用不透明材质，并保留用户所选档位供退出该模式时恢复。
- 浮层打开时检查与背后正文的重叠可读性。前景正文和数字目标对比度 ≥ 4.5:1，焦点环与邻接区域目标 ≥ 3:1。用深浅两种纯色背景与复杂壁纸实测浅／深色，必要时调整对应主题的文字和材质底色。

### 7.3 红线处日期标题

| 布局 | 标准档基准字号 | 字重 | 行高 |
| --- | ---: | ---: | ---: |
| 紧凑窗（360 px 参考宽度） | 18 px | 660 | 1.25 |
| 更窄的紧凑窗（沿用现有窄窗样式断点） | 17 px | 660 | 1.25 |
| 展开窗 | 22 px | 660 | 1.25 |

标题继续乘现有 `--font-scale`（1 / 1.15 / 1.30 / 1.45），计数保留现有独立字号。默认档按 360 × 620 核对两项同排。340 × 520 窄窗和最大字号下，空间不足时把计数排到标题下方，避免标题或计数被省略、裁切或重叠。用最长日期文案和三位数计数做回归。

### 7.4 实施顺序与验证

1. 基于 `dev` 现有日期网格实现光束和降级，保持日期选择与键盘行为。
2. 复用 `src/lib/appearance.ts` 的统一档位，在 `src/styles.css` 和必要的外壳材质结构中调整合成。先用黑白背景验证 60% 标准，再覆盖状态面板与浮层。
3. 调整 `.agenda-heading h2` 与标题行布局，覆盖三个窗口尺寸和四档字号。
4. 跑前端与真实 WKWebView 检查。以两种背景采样边框和未覆盖文字的平坦表面。60% 时由背景变化引起的通道差应约为原背景通道差的 40%（目标误差 ±3 个百分点）。100% 对两种背景的采样差维持现有回归阈值。覆盖冷启动、滑动 55%→60%→100%、重启恢复、失焦／聚焦、原生拖动、展开／收起和浮层打开。
5. 真机覆盖 340 × 520 / 360 × 620 / 900 × 640 和浅深主题。检查普通／选中／跨月悬停、快速扫过、键盘焦点、减少动态、降低透明度、空态与有事项。运行 `npm run check`、`npm run test:webkit`、版本一致性检查及仓库要求的 Rust 测试和构建检查。

## 9. 实施记录与验证（v0.3.10 / I-045）

### 9.1 实现范围

- 日期格：恢复仅鼠标指针触发的 900 ms 单圈蓝青边缘光束，1.5 CSS px SVG 描边；移动段采用 `stroke-dasharray: 16 84` 的短划，`stroke-dashoffset` 从 0 线性走到 -100，结束帧移动段透明，只保留既有静态淡环，不残留移动 trace。光束沿现有圆角、不占布局；移动日期时旧格立即清除并重启新格，离开、滚动、切视图、失焦、开始拖动和触摸均清理；键盘 `:focus-visible` 为独立外环，可与指针悬停同时显示，键盘本身不启动光束；同页方向键/选择不熄灭悬停，只有跨页等确实换视图时清除。`prefers-reduced-motion: reduce` 与动画不可用时直接显示静态淡描边（移动段 opacity 0）。
- 材质：外壳是唯一可见材质层，按用户 alpha 一次合成；顶栏、日历、日程头/筛选、清单/事项卡、空态、设置、新增/编辑浮层和控件面改为透明或极低 alpha 状态填充，避免 60% 外壳再叠 60% 面板。100% 使用确定性实色；55/60/75/95 按档透底；系统“降低透明度”强制不透但保留用户档位。
- 浮层：与浮层矩形相交的正文节点临时移除文字填充及装饰底色，不改变布局、位置、滚动或无障碍焦点，不铺全屏遮罩；浮层自身仍使用同一材质。
- 标题：紧凑 360 px 18 px、窄窗 340 px 17 px、展开 22 px，字重 660、行高 1.25，乘现有四档字号；默认计数同排，340 × 520 最大字号时降到标题下方，标题/计数不省略，清单保持滚动。
- 对比度：调整浅色次要/弱化文字、会议/逾期语义色和焦点环；跨月日期改用文字色而非父元素 `opacity`。不修改数据库、日历/提醒/筛选/布局业务或 WidgetKit UI。

### 9.3 测量结果

- 前端：152 项测试 / 16 个测试文件通过；核心 `src/lib` statements/lines 100%、branches 96.69%、functions 100%；Rust fmt/clippy 与 5 项测试通过；`npm run verify:version` 通过。
- Chromium：`verify-calendar-surface.cjs` 通过 99 项检查、0 失败、24 张截图；覆盖 340 × 520 / 360 × 620 / 900 × 640、四档字号、浅深主题、55/60/75/95/100、浮层无布局位移、短光束单格/移动/滚动/切视图/失焦/触摸/减少动态/动画不可用降级、键盘焦点与悬停同显，以及黑白背景 alpha。
- 最终像素 A/B：浅色 60% 选中日期与新增按钮的黑白背景通道差均为 96/255（背景贡献 37.6%），深色 60% 均为 94.67/255（37.1%）；浅深 100% 均为 0。两项控件、两种主题、两档透明度全部落在 60% 贡献 37%–43%、100% 无透底的目标内，证据 `final-pixels.json`。
- 原生 WKWebView：60% 时外壳、顶栏、日历、日程头、事项卡和窗口描边的纯黑/纯白通道差均为 102/255；55% 为 115，75% 为 64，95% 为 13，100% 为 0。深色 60% 的日历/顶栏/外壳/事项卡/窗口描边为 102，日程头 100.6（仍在 ±3 个百分点内）；1 px 面板分隔线约 94/92，属于装饰分隔线而非材质面。100% 首次绘制、ready、blur/focus、dragging、恢复显示均无背景泄漏。
- WKWebView 动效：光束 CSS 动画名为 `calendar-beam-trace`、时长 0.9 s、时间轴时长 900 ms；`stroke-dasharray` 为 16px/84px，450 ms 时 `stroke-dashoffset` 为 -50px、透明度 1；900 ms 后为 -100px、透明度 0、状态 `finished`，只保留静态环。键盘/滚动/切视图/触摸均清除；减少动态与移除动画时移动段透明度 0、静态环保留。
